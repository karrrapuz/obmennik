# Сохраняемый тестовый баланс

Актив `DEMO_TON` не является реальными TON. API не отправляет транзакций
в блокчейн и не создаёт счета CryptoBot. Платёжные провайдеры подключаются позже.

## API

Все маршруты требуют Telegram-сессию (Bearer).
Изменения требуют заголовок Idempotency-Key: повтор одного запроса не повторяет
движение средств; другая операция/параметры с тем же ключом дают 409.
При повторе возвращается актуальный баланс, а не старый снимок.

| Маршрут | Параметры |
| --- | --- |
| GET /api/wallet | Баланс, доступная демо-награда, последние 50 операций |
| POST /api/wallet/demo-topup | amount_nano: строка целого числа, source: wallet или cryptobot |
| POST /api/wallet/demo-withdraw | amount_nano: строка целого числа, destination: тестовый адрес |
| POST /api/wallet/demo-referral | Пустой объект; однократное получение доступной награды |

Все суммы API передаются строками целых nanoTON. В базе используются BIGINT,
во фронте BigInt. Преобразование в Number используется только для анимации
и отображения, а не для отправляемой денежной суммы.
Лимит одной операции 10 000 тестовых TON, баланса — 100 000.
Первоначально баланс 0, демо-награда 5 TON; инициализация однократная.

## Учёт

У пользователя три счёта: wallet, referral и treasury. Каждая операция имеет
две проводки с нулевой общей суммой. Начальная награда попадает на referral,
её получение переводит сумму на wallet. Вывод возвращает средства на
демонстрационный treasury; реального внешнего перевода нет.

Все движения и ключ операции сохраняются одной транзакцией. Блокировка
пользователя сериализует конкурентные списания и повторное получение награды.
Отложенные триггеры PostgreSQL проверяют нулевую сумму проводок, минимум две
проводки на операцию и соответствие остатков проводкам. HTTP API не предоставляет
редактирования или удаления журнала. Счета и проводки изолированы по владельцу
составными внешними ключами.

## Интерфейс

WalletProvider — единый баланс для профиля и хедеров обмена/залога. Данные
обновляются при фокусе окна. История показана в профиле.
Выдача, погашение, продление и автоплатёж демо-займов используют этот же
серверный журнал. Правила описаны в DEMO_LOANS.md. Снимки имеют монотонную
revision: поздний ответ не может откатить более новое состояние интерфейса.

При сетевой ошибке, HTTP 408 или 5xx клиент сохраняет ключ неопределённой
операции в памяти и обновляет баланс. Явный повтор использует тот же ключ.
После полного закрытия вкладки память ключей не сохраняется: перед новой
операцией нужно сверить восстановленные баланс и историю.

## Проверки

SQLite-контракты проверяют типы/точность сумм, лимиты, владельца, повторные
запросы, награду, перезапуск и сверку проводок. PostgreSQL проверяет два
одновременных вывода, два получения награды и отказ при несбалансированном
журнале или изменении остатка без проводок. В CI используется отдельная база.
