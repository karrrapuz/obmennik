# Заглушка поставщика подарков

Пока нет покупателя и его инфраструктуры, приложение работает без внешнего
приёма и отправки подарков. Текущий TELEGRAM_BOT_TOKEN нужен для проверки
входа в Mini App; он не означает подключённое хранение Telegram-подарков.

## Режимы

GIFT_PROVIDER_MODE=demo (по умолчанию) использует локальный каталог и прежние
тестовые операции. Пять стартовых экземпляров выдаются один раз. Пополнение,
обмен и вывод изменяют только PostgreSQL; ничего в Telegram не отправляется.

GIFT_PROVIDER_MODE=disabled отключает все demo-изменения инвентаря и создание
новых займов с HTTP 503. Автоматической выдачи стартовых подарков нет.
Сохранённые подарки, договоры и проводки не удаляются. Просмотр, погашение,
оплата процентов и продление существующих займов остаются доступны.
Старые резервы без долга возвращаются через /api/loans/repay бесплатно.

Другие значения, включая telegram/live, останавливают запуск с ошибкой
конфигурации. Неизвестный режим не превращается автоматически в demo.
Смена режима требует перезапуска API. Отключение интеграции не является
полной остановкой финансовых операций приложения.

GET /api/integrations/gifts требует Bearer-сессию и возвращает:

```json
{"mode":"demo","available":true,"simulated":true,"real_transfers":false}
```

В disabled available=false. Ответ не содержит токенов, адресов соединений,
данных аккаунта владельца бота или пользовательских подарков.

## Место подключения

backend/app/gift_provider.py содержит контракт и StubGiftProvider. Экземпляр
создаётся в create_app и передаётся инвентарю и займам. Локальный каталог,
первоначальная выдача и проверка доступности вынесены из HTTP-обработчиков.
Фронтовые маршруты и существующие ключи идемпотентности сохранены.

## Когда появится покупатель

1. Уточнить способ хранения/передачи подарков и доступные права конкретного
   Telegram-аккаунта или бота. Одного Bot API токена может быть недостаточно.
2. Реализовать отдельный реальный адаптер и подтверждённый импорт событий.
   Начислять подарки только по проверенному внешнему ID, владельцу и получателю.
3. Отправки выполнять через сохраняемую очередь/outbox вне DB-транзакции.
   Текущий контракт заглушки локальный: добавлять сетевой вызов внутрь
   require_available/initial_gifts/deposit_catalog_id нельзя.
4. Добавить внешние ID экземпляров, дедупликацию событий, резервы доставки,
   сверку неоднозначных результатов и повторные попытки без повторной отправки.
5. Перед реальным запуском отделить демонстрационные подарки и DEMO_TON
   от реальных активов. Не считать sample catalog ID идентификатором Telegram.
6. Секреты подключить через окружение сервера, а не фронт или Git. Сначала
   проверить адаптер в отдельном окружении, затем включить реальный режим.

Это подготовленное место интеграции, а не готовая доставка через Telegram.
