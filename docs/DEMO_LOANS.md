# Серверные демонстрационные займы

Все суммы относятся только к DEMO_TON. Реальные подарки, блокчейн, рыночная
оценка, ликвидация и внешние платежи пока не подключены.

## Условия

Сервер выдаёт 1.200 TON за поддерживаемый свободный подарок. Срок 1 неделя:
возврат 1.240 TON; 2 недели: 1.280 TON. Суммы и сроки клиент получает из API,
а не задаёт при отправке операции. Расчёты используют целые nanoTON и часы сервера.

Оплата процентов продлевает на первоначальный срок без комиссии. Пакетное
продление добавляет 14 дней и стоит сумму процентов плюс 0.010 TON один раз
на весь пакет. Это прежние демонстрационные правила интерфейса; коммерческие
условия необходимо согласовать отдельно. Новый срок отсчитывается от большей
из дат: текущей даты сервера и прежнего срока возврата.

## API

Все маршруты требуют Bearer-сессию Telegram. Изменения требуют Idempotency-Key.
Повтор с теми же параметрами не повторяет списание; другой запрос с тем же
ключом отклоняется. Суммы ответа передаются строками целых nanoTON.

| Маршрут | Параметры |
| --- | --- |
| GET /api/loans | Займы, условия, согласованные снимки кошелька и инвентаря |
| POST /api/loans/create | gift_id, weeks: 1 или 2 |
| POST /api/loans/repay | gift_id |
| POST /api/loans/pay-interest | gift_id |
| POST /api/loans/extend | gift_ids |
| POST /api/loans/autopay | gift_id, enabled |
| POST /api/loans/quote | gift_ids; расчёт стоимости пакетного продления |

Блокировка пользователя сериализует изменения. Резерв подарка, проводки,
статус займа и квитанция запроса сохраняются одной транзакцией. Снять резерв
выданного займа через старый маршрут инвентаря нельзя. Недостаток баланса
не меняет ни деньги, ни сроки, ни резерв.

## Старые резервы

Подарки, зарезервированные прежним демо без серверной выдачи денег,
импортируются с legacy=true и нулевым долгом. Их можно бесплатно вернуть.
Задним числом деньги не начисляются, долг не создаётся.

## Автоплатёж

Включённый автоплатёж погашает весь долг после наступления срока, если
достаточно средств. Задача проверяет сроки каждую минуту и при загрузке
займов. Повторная проверка не списывает деньги дважды. При недостатке средств
повтор возможен через минуту. После погашения подарок снова свободен.
Один проход выбирает до 100 пользователей, исключая займы в минутной паузе
между попытками и legacy-записи. Сначала обрабатываются ещё не проверенные
или дольше всего ожидающие пользователи, чтобы очередь не застревала на первой сотне.
Проход возвращает служебные счётчики `selected`, `processed`, `failed` и
`discovery_failed`, без пользовательских данных. Ошибка одного пользователя
откатывает его транзакцию, не останавливая остальных; следующий проход может повторить её.

Бесплатный Render засыпает: точное время выполнения не гарантировано,
проверка догоняет сроки после пробуждения. Для реального сервиса нужен
постоянно работающий планировщик и отдельная политика просрочки/уведомлений.
