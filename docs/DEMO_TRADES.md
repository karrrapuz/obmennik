# Серверные цены и обмен DEMO_TON

Этот модуль не торгует реальными Telegram-подарками и не использует реальные
TON. Поставщик подарков остаётся заглушкой; котировки цен сейчас основаны
на локальном sample-каталоге, а не на рыночном API.

## Тариф и точность

Сервер оценивает предлагаемые подарки по базовой цене sample-каталога.
Цена получаемого подарка: базовая цена плюс TRADE_MARKUP_BPS / 100 процентов.
Настройка по умолчанию 500 означает демонстрационные 5%, не коммерческую
рекомендацию. Наценка задаётся только окружением сервера (0..10000).

Все расчёты используют целые nanoTON; дробные исходные цены разбираются
Decimal без float. Цена продажи округляется вверх до одного nanoTON
для каждого экземпляра. Сумма каждой стороны не превышает 100000 TON.

wallet_delta_nano = offered_nano - received_nano. При отрицательной разнице
сервер списывает доплату с кошелька; при положительной зачисляет остаток.
Для нулевой разницы денежная проводка не создаётся. Обе стороны должны
содержать хотя бы один подарок, максимум 100 уникальных ID.

## Котировка

POST /api/trades/quote принимает только offered_ids (ID принадлежащих
пользователю экземпляров) и received_ids (ID sample-каталога). Цены, наценку,
суммы, владельца и срок действия клиент передавать не может.

В ответе сохраняются id, expires_at, status, asset, source, source_version,
markup_bps, offered/received с unit_nano, offered_nano, received_nano,
wallet_delta_nano и required_balance_nano. Все суммы представлены строками.
source=sample явно обозначает происхождение. SHA-256 версии фиксирует
использованный набор базовых цен. GET /api/trades/quotes/{id} доступен
только владельцу, чужой или неизвестный ID даёт 404.

TRADE_QUOTE_TTL по умолчанию 120 секунд, допустимо 30..600. Для будущего
внешнего провайдера expires_at ограничивается сроком годности цен valid_until.
Просроченный источник или внешний источник без valid_until отклоняется.
Sample-провайдер статичен и не выдаётся за свежие рыночные данные.

Котировка фиксирует цену, но пока не резервирует подарки: при подтверждении
повторно проверяются владение, отсутствие залога и доступность каталога.
После истечения срока подтверждение отклоняется, необходим новый расчёт.
Изменение настроек цен не переписывает уже выданную действующую котировку.

## Подтверждение и восстановление

POST /api/trades/execute принимает quote_id и Idempotency-Key. Блокировка
пользователя сериализует обмен с выводом, залогом и другими списаниями.
Замена подарков, денежная проводка, статус executed и квитанция запроса
сохраняются одной транзакцией. Недостаток средств или недоступность любого
подарка не меняют остальные подарки и деньги.

PostgreSQL использует блокировку строки пользователя. Локальная SQLite
получает блокировку записи до чтения изменяемого состояния; обмен,
инвентарь, кошелёк и автоплатёж используют общий механизм сериализации.
Префиксы ключей trade:, loan:, auto: и __ зарезервированы для внутренних
проводок: публичные операции кошелька отклоняют такие ключи с HTTP 422.

Повтор успешного quote_id, даже с новым ключом, не исполняет обмен повторно.
Одинаковый ключ с другим quote_id даёт 409. Возвращается актуальный общий
снимок revision/quote/inventory/wallet; поздний ответ не должен откатывать
более новое состояние клиента. После сетевой неопределённости клиент
сохраняет quote_id и ключ для явного повтора, не создаёт другой обмен молча.
После перезагрузки канонические подарки и баланс восстанавливаются из API.

Старый POST /api/inventory/demo-exchange возвращает 410: обход котировки
и расчёта через прежнюю замену инвентаря закрыт. Режим disabled поставщика
блокирует новые котировки и новые исполнения, не стирая историю и не
препятствуя чтению результата уже исполненной котировки.

## Реальный источник цен позже

PriceProvider в backend/app/pricing.py отделён от обмена. Будущий адаптер
должен заранее получать проверенные данные, фиксировать источник/версию и
valid_until. Сетевой запрос к площадке внутри транзакции обмена недопустим.
Нужны ограничения запросов, кэш, проверка валюты и единиц, сопоставление
коллекции/модели и отказ при устаревших/аномальных данных.

Один из кандидатов — [официальный GiftAsset API](https://github.com/GIFT-ASSET/gift_asset_api/blob/main/DOCS.md):
документация описывает collection/model floors и авторизованный доступ.
До подключения необходимо подтвердить ключ, актуальный API-хост и условия.
Рыночный floor не гарантирует возможность купить конкретный подарок по этой
цене. Доступ к платным API и отправка реальных торговых операций не включены.
